## Task B6.2 First Node

Manual setup of project: 

```sh
mkdir ~/iot-systems
cp -R "$IOTEMPOWER_ROOT/lib/system_template" ~/iot-systems/demo
cd ~/iot-systems/demo
mv node_template test01
```

This was the approach according to the tutorial. Since there were already two demo folders, I copied and renamed the project folder 'demo01' within the folder ~/iot-systems.

In the file system.conf, it states that there is a global conf file /etc/iotempower.conf. This does not exist. So I overwrote it with the SSID, Password and IP address of the Raspberry Pi. 

This worked and after changing the setup.cpp file as in the tutorial and screenshots, the ESP sent data to that particular topic as can be seen [here](./screenshots/B6_2_mqtt_serial_monitor.png).


---


After this step, i unplugged the ESP from the raspberry pi and tested if it would work with an external power source and it also does.

The next step is to make the led blink when the button is pressed. I changed the setup.cpp to this: 

```cpp
input(button1, D3, "released", "pressed").with_debounce(5);
output(blue, ONBOARDLED).inverted();
```

To develop in Node-red, I installed it onto my PC and open it using the bash command: 

```sh
node-red
```

Then i created a very basic flow to control the led and to read the mqtt topic created by the ESP. A demo of this task can be seen [here](./demos/B6_2_demo.mp4)

## Task B6.3

First step is to create a new node with: 

```sh
iot x create_node_template
```

The node was created and i renamed it to: second_node.

I used another Wemos D1 mini, so Ididnt have to change the file node.conf.

Then adjusted the setup.cpp to: 

```cpp
input(b1, D3, "up", "down");
```

I then flashed it onto the ESP. For that, I plugged in the esp with a usb cable and used the command from earlier: 

```sh
iot x deploy serial. 
```

For some reason, for both nodes, it did not work the first time. It got stuck after: Compiling .pio/build/wemos_d1_mini/src/text_display_buffer.cpp.o

For node 1, it just failed and after retry, it worked. For Node 2, I had the same experience. 

Although, Node 2 was a whole lot harder to get working. It seems that maybe I took the wrong microcontroller, or my wifi at home was used too heavily or the microcontroller is defect, because I was not able to flash to one particular microntroller (With the label D1 mini and Andruid cable adapter). But I also did this, when the entire family was in the wifi, so maybe the raspberry pi struggled to fetch the libraries through my network. 

At the end of the day, I switched the microcontroller and performed the task late at night, when I was the only one in the network, flashing the microntroller worked in a couple of seconds. 

After the second node finally worked, I could work on the Node-Red flow.

The flow was very basic and only consisted of MQTT-In Nodes, a switch do decide whether the value is "up" or "down" and a Change-Node for each option. At the end, the value is sent to the topic of Node 1. 

Unfortunately, I couldnt do the exercise with the M5StickC+2 as I did not have that piece of hardware, when i finished the exerice. But from a technical standpoint, there are only a few changes, I would have to do: 

- Adjust node.conf (first checkout the documentation what microcontroller is part of the M5StickC+2 and write that value in node.conf).

Apart from that, pretty much everything stays the same.

## Task B6.4 Text receiver

As I dont have the M5StickC, I just used the provided OLED display provided together with a Wemos D1 Mini. 

For this task, i created a new node and changed the setup.cpp to: 

```cpp
// small Wemos D1 Mini SSD1306 64x48 display shield
U8G2_SSD1306_64X48_ER_F_HW_I2C u8g2(U8G2_R0); // R0 no rotation, R1 - 90°
display(oled, u8g2, font_tiny);
```

The first couple times, it did not work. The retrieval froze and the RAM of the Pi was maxed out. After a couple of tries it did work normally. 

And after sending some test-data with the following command, the text showed up on the screen:

```sh
iot x mqtt_send oled "Hello"
```

After that, i created a Node-Red flow that sends text to the display. The flow also write "&&clear " in front of the text input to clear the screen before something is printed. The flow can be seen [here](./screenshots/B6_4_flow.png).

Those pictures demonstrate the functionality of our system [img1](./demos/B6_4_display.jpeg) [img2](./demos/B6_4_display_2.jpeg).
